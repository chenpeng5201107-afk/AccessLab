## 一、作品简介（一段话版）

AccessLab 是一个面向学生开发者的**交互式网页无障碍学习实验室**。

它不把 WCAG 条文当成背诵清单，而是把三类最常见的无障碍缺陷做成可以动手改的真实网页组件：
色彩对比度不足、表单标签没有真正关联、键盘焦点看不见。用户在页面里**体验问题 → 动手修复 → 重新验证 → 带走代码**，
每一步的检测数值都由浏览器里的真实 DOM 和 WCAG 2.2 算法实时算出来，不是配图、也不是写死的结论。
三个实验跑完，`#/report` 会把这次会话里"检测到了什么、真的改了什么、改了之后复没复核、还有什么要人工确认"
汇总成一份可以复制或下载的 Markdown 报告。

**在线体验：https://accessibility-lab-3g6uvbn5duq.qoder.zone**（无需登录、无需 API Key）

## 三、功能清单

### 色彩对比度实验

- 取色器调文字色 / 背景色，预览与对比度数值**实时**联动。
- 对比度由 WCAG 2.2 相对亮度算法现场计算（`#000` vs `#fff` = 21:1，同色 = 1:1），不写死。
- 判定当前版本只看**普通文本 AA（SC 1.4.3，≥ 4.5:1）**一条，页面明说这一点。
- 默认案例 `#777777` / `#FFFFFF` 实测 **4.48:1，未达 AA** —— 就是那种"看着还行但其实不合格"的配色。
- 「生成修复建议」用二分逼近算出改动最小的达标色：`#777777 → #767676`，比值 **4.48:1 → 4.54:1**。
- 应用到预览 → 撤销回原状 → 复制可粘贴的 CSS，三步都能真实回退。
- 输入非法色值时旧建议与旧快照立即失效、修复功能暂停，不会偷偷沿用上一次的结果。

### 表单标签实验

- 「学生信息登记」示例表单：姓名旁边那行字**故意**只用 `<span>`，视觉上看得见，`label ↔ input` 之间没有任何关联。
- 「重新检测」的结论来自浏览器真实 DOM：是否有关联的可见标签、可访问名称从哪来、检测到的控件名称。
- 明确区分两件常被混为一谈的事：**缺少关联的可见标签** ≠ **完全没有可访问名称**（placeholder 能给到名称，但不算正确关联的可见标签）。
- 「修复标签关联」后 DOM 真的变成 `<label for="student-name">`：`input.labels` 从 `0` 变 `1`、点 label 能聚焦输入框、复检问题数归 0，已输入内容不丢。
- 修复前后的 HTML 并排对比、真实改动行高亮、可复制，展示的 `id` / `for` 就是页面实际在用的值。

### 键盘焦点实验

- 「不使用鼠标，你还能找到自己正在操作的位置吗？」
- 三个原生 `<button>` 都有真实行为（展开详情 / 写入已保存列表 / 撤回上一次保存），不是装饰。
- 缺陷态：键盘**能走到**按钮，但 `:focus-visible` 写了 `outline: none`，屏幕上看不出焦点在哪。
- 「修复焦点指示」后组件样式状态真的切成 `outline: 3px solid #4338ca; outline-offset: 3px`；
  同一批按钮、同一套行为，只换焦点指示；「重置实验」可回到缺陷态再看一遍。
- 记录修复前 / 修复后各自的**键盘导航到达次数**，鼠标点击不计入。
- 走完五步人工验证后点「我已完成观察」，页面给出固定结语，不把"改了 CSS"说成"符合全部规范"。
- 缺陷样式**只作用于实验区按钮**（`.kf-demo-btn*`），站点自身的导航与按钮焦点始终可见。

### 统一成果报告

- 把「首页 → 色彩 → 表单 → 键盘 → 报告 → 导出」这条链闭合，切路由不丢，刷新即清空（内存台账，不写任何存储）。
- 四项计数分开：**已记录 / 已实际执行修复 / 已进行修复后复核（含人工键盘体验）/ 仍需人工验证**，
  **不给总分、不给百分比、不给"整体合规"**。
- 人工验证分三组，互不冒充：**仍待你本人完成的观察** / **已由你确认完成的观察** / **建议额外进行的辅助技术与真实场景验证**。
- 未运行的实验显示「未记录」，不会显示成"0 项问题"或"已通过"。
- 复制或下载 Markdown，内容与页面展示**逐字同源**；纯浏览器本地完成，不上传任何数据。
- 「清空本次实验记录」先要求确认，取消则原样保留。

## 四、技术栈

| 层 | 选型 |
| --- | --- |
| 框架 | React 19 + TypeScript 5.9 |
| 构建 | Vite 8 |
| 样式 | Tailwind CSS 4（`@tailwindcss/vite`） |
| 图标 | lucide-react |
| 测试 | Vitest 5 + jsdom |
| 路由 | 自实现 hash 路由（静态托管下刷新不依赖服务端 rewrite） |

hash 切换 **0 请求**，不接任何第三方 API，不采集任何数据。

## 八、这个产品不做什么（诚实边界）

AccessLab 只对**它自己内置的示例组件**做教学性检测与修复。它**不是**：

- 不是整站 WCAG 合规扫描器，不输出总分、百分比或"已合规"结论；
  报告页逐字写着「**本报告仅针对 AccessLab 内置示例，不是网站 WCAG 合规认证。**」
- 不模拟屏幕阅读器的语音输出，也不声称已用读屏实测；
- 不检测大文本对比度（AA 3:1）、非文本对比度（SC 1.4.11 3:1）、AAA 档（SC 1.4.6 7:1）等条目 —— 页面「未检查项」里逐条列出了阈值和未覆盖范围；
- 不保存示例表单里的任何输入，不上传数据，不写 `localStorage` / 后端；
- 不引入登录、统计、动画库或图表库。

产品自身的无障碍处理是**示范性质**：可跳转主内容的 skip link、语义化 landmark、连续不跳级的标题层级、
键盘完整可操作、可见焦点环、`role="status"` 播报、遵守 `prefers-reduced-motion`。
