# AccessLab 演示视频脚本（目标 75–90 秒）

> 原则：**画面里出现的每一次数值变化、每一处 DOM 变化，都必须是真实运行产生的。**
> 禁止用静态图、假动画或后期换字冒充修复结果。可以剪辑的是节奏和口播，不能剪辑的是"修复真的发生了"这件事。
>
> 录制前请先完成 `demo-checklist.md` 的准备项。
>
> **口径区分**：本脚本要求的是**你本人接下来要录的视频**用真实按键、真实渲染。
> 已归档的 Day 7 / Day 8 截图与 JSON 读数是**自动化脚本向真实浏览器发送键盘事件**得到的，
> 两者不要混着写：截图不能声称"真人操作"，视频也不能拿截图代替。

### 段落 1 · 0:00–0:10 ｜开场：问题与主张

| 项 | 内容 |

### 段落 2 · 0:10–0:30 ｜色彩对比度实验：发现 → 修复 → 撤销

| 项 | 内容 |
| --- | --- |
| 页面 | `#/contrast` |
| 操作 | ① 点首页「开始第一个实验」进入 → ② 读数区显示 `当前对比度 4.48:1 未达 AA` → ③ 点「**生成修复建议**」 → ④ 点「**应用该修复**」，预览文字当场变深 → ⑤ 点「**撤销本次修复**」回到 4.48 |
| 画面要点 | 焦点会**自动落到新出现的结果块**上（Day 7 修的焦点交接）——给这一瞬 0.5s，别急着切 |
| 解说词 | 「我来生成一个建议：算法把文字往纯黑方向微调，取改动最小的达标色——`#767676`，对比度 **4.54:1，达到 AA**。点应用，预览当场变深；点撤销，回到 4.48。整个过程我什么都没改，是页面自己在算。」 |
| 关键数据 | 屏幕压字：**4.48:1 → 4.54:1 ｜ 建议色 #767676 ｜ WCAG 2.2 SC 1.4.3** |
| 镜头 | 读数区特写 → 建议块特写 → 预览区左右对比（同帧内完成，不要剪切前后） |
| 必须真实 | ✅ 应用/撤销必须现场真点，预览颜色变化必须是浏览器渲染结果 |
| 可后期 | 段落间删除等待；口播补录 |

> 可选加 3 秒（若时长够）：输入 `#12zz` → 页面出现 `aria-invalid` 红字提示、修复区暂停、生成按钮消失。
> 解说：「输入非法值，旧建议立刻失效——它不会拿一个过期结论糊弄你。」
> **若时长紧张优先剪掉这一段**，它是加分项不是主线。

### 段落 3 · 0:30–0:45 ｜表单标签实验：真实 DOM 修复

| 项 | 内容 |
| --- | --- |
| 页面 | `#/form-label` |
| 操作 | ① 点「进入表单标签实验」→ ② 检测结果区显示「姓名」缺少关联的可见标签（电子邮箱那一行显示通过）→ ③ 点「**修复标签关联**」→ ④ 复检问题数归 0 → ⑤ **鼠标点一下"姓名"那行文字，焦点跳进输入框** |
| 画面要点 | 下方「修复前 / 修复后」HTML 对比：`<span>姓名</span>` → `<label for="student-name">`，改动行高亮 |
| 解说词 | 「屏幕上'姓名'这两个字一直看得见，但它和输入框之间没有任何关联——读屏软件念到这个位置，可能只说'编辑框'。点修复，DOM 真的换成了 `<label for="student-name">`：注意 `input.labels` 从 0 变成 1。现在点这行字，焦点跳进输入框了。」 |
| 关键数据 | 屏幕压字：**`input.labels` 0 → 1 ｜ 复检问题数 → 0** |
| 镜头 | 检测结果 → 特写前后 HTML 对比区的那两行差异 → 回到表单演示点 label |
| 必须真实 | ✅ 必须点一次 label 让"聚焦输入框"这件事在画面里发生，这是修复生效最直观的证据 |
| 可后期 | 结果区的滚动可以剪 |

### 段落 4 · 0:45–1:05 ｜键盘焦点实验：前后对比（本片最强的一段）

| 项 | 内容 |
| --- | --- |
| 页面 | `#/keyboard` |
| 准备 | **必须用真实物理键盘（或可靠的系统级按键注入），不能靠鼠标点** |
| 操作 A（缺陷态） | 按 Tab 依次走过「查看详情 / 保存选择 / 返回上一步」，**画面里三个按钮毫无变化** |
| 解说 A | 「我先不用鼠标。按 Tab……现在焦点在哪个按钮上？看不出来吧。键盘能走到，但 `:focus-visible` 被写成了 `outline: none`。」 |
| 操作 B（修复） | 点「**修复焦点指示**」 |
| 操作 C（修复后） | 再按一遍 Tab，**这次出现 3px 靛蓝焦点环**，三站逐一可见 |
| 解说 C | 「修复只换了一条规则：`outline: 3px solid #4338ca`。同一批按钮、同一套行为——再按一遍 Tab，这次看得见。」 |
| 关键数据 | 屏幕压字：**`:focus-visible { outline: none }` → `outline: 3px solid #4338ca; offset 3px`** |
| 镜头 | 全程**同一个机位、同一帧尺寸**拍按钮区，让前后差异只由页面本身产生；**严禁**用分屏左右对比（会被质疑两帧不是同一次运行） |
| 必须真实 | ✅✅ **这段绝对不能用动画或前后拼贴代替真实按键。**焦点环是浏览器渲染的，一次录制即可 |
| 可后期 | 第二次按 Tab 的中间站可以剪掉一到两站，保住"看得见环"就够 |

> **不要**在画面里出现"已符合 WCAG"之类的字样。这一页末尾的结语是页面自己写的固定句子，可以扫一眼带到：
> 「本次实验只验证了指定组件的焦点显示与基本操作，不能代表整个网站已经符合全部无障碍规范。」
> 这句话留在画面里 1 秒就好——它是这个作品可信度的一部分。
>
> 收尾可以顺手点一下「我已完成观察」（3 秒），给段落 5 的报告页制造"已由你确认"那一组。

### 段落 5 · 1:05–1:20 ｜统一成果报告与导出

| 项 | 内容 |
| --- | --- |
| 页面 | `#/report` |
| 操作 | ① 点「查看统一成果报告」→ ② 首屏四项计数（真实值参考：**已记录 3/3、已实际执行修复 3/3、已进行修复后复核 3/3、仍需人工验证**）→ ③ 快速下滚过人工验证三组 → ④ 点「**复制 Markdown 报告**」（出现"已复制完整 Markdown 报告，内容与上方展示逐字一致"）→ ⑤ 或点「**下载 .md 文件**」并展示落盘文件 |
| 解说词 | 「报告把这次会话里我真做过的部分汇总起来：三个实验都留下了修复前后的证据。注意它不给总分、不给百分比——人工要验的还留着，而且分成三组：我还没做的、我已经确认的、以及建议我另外拿真机读屏去验的。它不会替我说 NVDA 测过了。最后，这份 Markdown 和页面上的内容逐字同源。」 |
| 关键数据 | 屏幕压字：**不给总分 ｜ 人工验证分三组 ｜ 复制 / 下载 Markdown（6197 字符，落盘 13577 B）** |
| 镜头 | 计数区 → 人工验证三组标题（能看清"（N 项）"）→ 复制成功提示 → 下载文件出现在下载目录 |
| 必须真实 | ✅ 三项实验必须是本片里真做过的，**不能为了这条视频预跑一遍、报告却显示没做过的状态** |
| 可后期 | 长滚动过程加速到 1.5–2 倍；文件落盘可以单独截 1 秒 |

> ⚠️ **报告页只存在于当前浏览器会话**：刷新或重开标签页就回到 `0 / 3`。
> 所以段落 5 必须和段落 2–4 在**同一次连续会话**里录完，中途不能刷新、不能重开页面。
> 这是本片最容易翻车的技术点，见 `demo-checklist.md` 第 3 节。

## 3. 素材与工具

- 屏幕录制：**系统自带工具即可** —— Windows `Win+G`（Xbox Game Bar）或新版「截图工具」的区域录屏；
  macOS `Cmd+Shift+5`。**不要为此引入任何 npm 依赖或剪辑库。**
- 局部放大：**优先用浏览器缩放（`Ctrl` + `+`）或录制时裁切**，不要用后期推拉制造"放大"。
- 字幕：论坛/视频平台自带字幕，或一条简单的 `.srt`。
- 导出：1080p、H.264 MP4，控制在 30 MB 以内方便上传（超出就降到 720p）。

## 4. 解说词全文（连贯版，约 240 字 / 90 秒）

> 「这段正文是 `#777777` 压在白底上，看着挺正常——实测对比度 4.48:1，没达到 WCAG 2.2 普通文本 AA 的 4.5:1。差 0.02。
> 这是 AccessLab，一个网页无障碍动手实验室。我生成一个修复建议：算法把文字往黑的方向微调，取改动最小的达标色 `#767676`，4.54:1 达到 AA。点应用，预览当场变深；点撤销，回到原样。
> 表单这里，'姓名'两个字一直在屏幕上，但它和输入框没有任何关联，读屏软件可能只念得出'编辑框'。点修复，DOM 真的换成了 `label for`，复检问题数归零，点这行字焦点就跳进输入框。
> 现在我把鼠标放到一边。按 Tab——焦点在哪？看不出来，因为 `outline` 被写成了 `none`。我只换一条规则：3px 的靛蓝焦点环。再按一遍 Tab，这次看得见。
> 三个实验跑完，报告把成果汇总起来：不给总分、不给百分比；人工还要验的分成三组留着，它不会替我说读屏测过了。这份 Markdown 和页面内容逐字同源，可以直接复制带走。
> 一个字符、两个属性、删一行 CSS——无障碍的成本从来不高，高的从来是想到它。AccessLab：让网页的障碍，看得见、改得掉。」

## 5. 录制时的红线（不得越界）

| ❌ 不要 | ✅ 要 |
| --- | --- |
| 用静态图/动效冒充"修复发生了" | 现场真点、真实渲染 |
| 键盘段落用两张截图拼前后 | 同一机位一次连续录制 |
| 为了报告好看而预先跑一遍再刷新回来 | 与前面段落同一会话连续录完 |
| 声称"NVDA / VoiceOver 实测" | 只说"静态语义与可访问性树已核对，读屏仍待真机验证" |
| 屏幕压字写"WCAG 合规认证通过" | 写"仅针对内置示例的教学性检测" |
| 把脚本机械耗时说成"评委 3 分钟体验时长" | 不提计时，或注明是设计目标 |
| 用localhost 画面参赛 | 用公网地址，地址栏可见 |
